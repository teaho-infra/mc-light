# mc-light 多状态区分设计:等待授权闪烁

**日期**:2026-07-13
**状态**:已批准设计,待编写实现计划
**关联**:在 [2026-07-09 基础设计](2026-07-09-mc-light-design.md) 之上扩展

## 1. 概述

在现有两态(干活中=常亮金 / 空闲=灭)之上,新增第三态**"等待授权"=金色闪烁**。当 Claude Code 需要用户点允许(权限请求)时,M 灯从常亮切为闪烁,提示"在等你";授权后恢复常亮,回合结束后熄灭。

这用掉原设计预留的协议位 `2`,协议保持向前兼容(老固件忽略 `2`)。

## 2. 目标与非目标

### 目标
- 区分三态:干活中 / 等待授权 / 空闲,且"等待授权"用闪烁明显区别于常亮
- 授权后灯自动恢复常亮,直到回合结束才灭
- 沿用现有架构:hook 短命脚本 → 单字符 → 固件自持状态
- 硬件、3D 打印件、设备发现/静默失败逻辑一律不动

### 非目标(YAGNI)
- 呼吸/渐变闪烁(本次用硬切换亮灭,最简单)
- 更多状态颜色(出错、完成提示等,暂不做)
- 周期续命看门狗(维持现有 10 分钟兜底)

## 3. 状态与协议

| 状态 | 含义 | 协议字符 | 灯效 |
|---|---|---|---|
| 干活中 | agent 正在跑 | `1` | 常亮金 |
| 等待授权 | 需要用户点允许 | `2` | 金色闪烁(亮 0.5s / 灭 0.5s,周期 1s) |
| 空闲 | 回合结束 | `0` | 灭 |

- 单字符 ASCII,沿用原协议。`2` 为原设计预留位。
- 未知字符固件仍忽略、不崩溃 —— 向前兼容不变。

## 4. 事件映射(Claude Code hooks)

| 事件 | 发送 | 时机 | 参数 |
|---|---|---|---|
| `UserPromptSubmit` | `1` | 用户提交输入,agent 开始干活 | `on` |
| `Notification` | `2` | 需要授权 → 开始闪烁 | `wait` |
| `PostToolUse` | `1` | 工具执行完(含授权后那次)→ 恢复常亮 | `on` |
| `Stop` | `0` | 回合结束 → 灭 | `off` |

新增 `Notification`、`PostToolUse` 两个 hook。

**设计理由**:
- `Notification` 在 Claude Code 需要用户授权时触发,是"等待授权"的信号源。
- 授权后没有专门的"授权完成"事件把灯切回常亮;改用 `PostToolUse`——被授权阻塞的工具只有在用户允许后才真正执行,执行完触发 `PostToolUse` → 发 `1` 恢复常亮。正常干活时每个工具执行完也发 `1`,但对常亮态幂等、无害。
- `Notification` 不止授权时触发(空闲等待用户回话也可能发),但那种场景通常 `Stop` 已先把灯灭了,影响可忽略。

## 5. 组件改动

### 5.1 固件 `firmware/code.py`(核心改动)
主机脚本是短命的、只发一次字符即退出,因此**闪烁必须由固件自持**。

- 引入当前模式:`OFF` / `SOLID` / `BLINK`。
- 收到 `1` → SOLID(常亮金);`2` → BLINK;`0` → OFF;未知字符忽略。
- BLINK 模式:主循环用 `time.monotonic()` 每 0.5s 翻转灯亮/灭,直到收到 `1` 或 `0` 才停。
- 看门狗:SOLID 与 BLINK 都纳入现有 10 分钟兜底;超时自动灭(等授权时用户走开也会自动熄)。
- 沿用现有 `time.sleep(0.05)` 轮询主循环结构。

### 5.2 主机脚本 `host/mc_light.py`(小改动)
- 在 `COMMANDS` 字典新增 `"wait": b"2"`(现有 `on`→`b"1"`、`off`→`b"0"` 不变)。
- 其余逻辑(按 VID 发现设备、超时、静默失败返回 0)完全不动。

### 5.3 Hook 配置示例 `hooks/settings.{ubuntu,windows}.json`(补充)
- 两份示例各新增 `Notification`(跑 `mc_light.py wait`)与 `PostToolUse`(跑 `mc_light.py on`)两个 hook。
- Ubuntu 用 `python3`,Windows 用 `python`,与现有一致。

### 5.4 文档 `README.md`(补充)
- "工作原理"补上三态与新事件映射;验收步骤补一条"触发授权 → 灯闪 → 允许 → 常亮"。

## 6. 异常处理与边界

沿用原则:hook 脚本永远快速、静默、不报错退出;灯故障绝不干扰 Claude Code。新增边界:

| 情况 | 处理方式 |
|---|---|
| 等授权时用户走开 | BLINK 纳入 10 分钟看门狗,超时自动灭 |
| `Notification` 非授权场景触发 | 灯会闪,但一般 `Stop` 已先灭;可接受 |
| 收到 `2` 的老固件 | 忽略(向前兼容) |
| BLINK 期间收到 `0` | 立即灭,停止闪烁 |

## 7. 测试策略

### 7.1 固件层
- 串口发 `1`/`2`/`0`,肉眼确认 常亮 / 闪烁(亮灭各约 0.5s)/ 灭。
- 发未知字符,确认灯不变、不崩。
- BLINK 态静置,确认约 10 分钟(测试可临时改短)后自动熄灭。
- BLINK 态发 `1` 确认切常亮;发 `0` 确认立即灭。

### 7.2 主机脚本层
- 命令行跑 `mc_light.py wait`,确认灯开始闪。
- 拔灯再跑 `wait`,确认静默退出、返回码 0。

### 7.3 集成层
- 在 Claude Code 里触发一个需授权的操作(如运行命令),确认灯开始闪。
- 点允许,确认灯恢复常亮;回合答完确认灭。

### 验收标准
干活时 M 常亮金;需要授权时 M 闪烁;授权后回到常亮;答完灭。不插灯时 Claude Code 完全正常。
