# mc-light 设计文档

**日期**:2026-07-09
**状态**:已批准设计,待编写实现计划

## 1. 概述

mc-light 是一个感知 Claude Code agent 运行状态的实体指示灯。灯做成麦当劳金拱门 "M" 的造型,通过 USB 连接电脑:当 Claude agent 正在干活时,M 亮起金色;agent 空闲(等待用户输入)时,M 熄灭。

面向用户:单片机小白。因此硬件与软件方案均以"最简单、最难失败、免焊接"为首要目标。

## 2. 目标与非目标

### 目标
- agent 运行时亮灯、空闲时灭灯,状态精确
- 免焊接、零常驻服务、代码量最小
- 跨平台:Windows 与 Ubuntu 同一份代码
- 灯设备缺失或故障时,绝不干扰 Claude Code 的正常使用

### 非目标(YAGNI)
- 无线 / WiFi 联网(当前不做,硬件可后期升级)
- 多状态颜色区分(当前只做两态,但协议预留扩展)
- 呼吸灯 / 渐变等需要持续通信的动画效果
- 常驻后台服务

## 3. 硬件

### 主控
**Seeed XIAO RP2040**
- 自带 USB-C 口,直接插电脑
- 板载一颗 NeoPixel RGB 灯珠(WS2812 类型),即照亮 M 的光源,无需外接、无需焊接
- 运行 CircuitPython,改代码如同改 U 盘文件
- RP2040 芯片 USB VID = `0x2E8A`

### 灯效
- 一颗板载 RGB 灯珠整体背光,照亮 3D 打印的半透明金拱门 M
- M 尺寸约 6cm,板载灯珠亮度足够
- 默认颜色:麦当劳金黄色

### 物料清单
| 物件 | 说明 |
|---|---|
| XIAO RP2040 ×1 | 主控 + 板载 RGB 灯 |
| USB-C 数据线 ×1 | 必须是数据线,非纯充电线 |
| 3D 打印:半透明 M 外壳 + 底座 | 用户自行打印,PLA 半透明/白色 |
| (可选)导光/漫射结构 | 靠打印件壁厚实现,使发光均匀 |

后期若要做更大的 M,可外接一颗大灯珠,协议不变。

## 4. 软件架构

### 数据流(单向)
```
Claude Code 事件  →  Hook 脚本(短命)  →  USB 串口  →  XIAO 固件  →  RGB 灯
```

系统三个部分,各自可独立理解与测试。

### 4.1 Claude Code Hooks(配置)
在 Claude Code settings 中注册两个 hook:
- `UserPromptSubmit`(用户提交输入,agent 开始干活)→ 运行脚本发 `1`(亮)
- `Stop`(agent 完成回复,回到空闲)→ 运行脚本发 `0`(灭)

这两个事件精确对应"运行中 vs 空闲"。

### 4.2 Hook 脚本 `mc_light.py`(电脑端)
极简 Python 脚本,接收一个参数(`on` / `off`):
1. 用 `pyserial` 的 `serial.tools.list_ports` 遍历所有串口,按 USB VID `0x2E8A` 自动锁定 XIAO 设备(不硬编码端口名)
2. 打开串口 → 写单个字符(`1` 或 `0`)→ 关闭
3. 串口操作加约 1 秒超时,绝不长时间挂起
4. 找不到设备 / 打开失败 / 写入失败 → 捕获异常,静默退出(返回码 0),不干扰 Claude Code

依赖:`pyserial`(纯 Python,跨平台)。

### 4.3 XIAO 固件 `code.py`(板子端,CircuitPython)
上电即运行的主循环:
1. 通过 `usb_cdc.data` 读**数据串口**(非 REPL 口;CircuitPython 数据串口被打开时不复位程序,故不会闪灯/掉线)
2. 读到 `1` → 灯亮(麦当劳金黄色);读到 `0` → 灯灭
3. 读到未知字符 → 忽略,不崩溃
4. 上电默认状态:灭
5. **看门狗兜底**:超过 10 分钟未再收到"亮"信号则自动熄灭,防止 Claude 异常退出(未触发 `Stop`)时灯常亮

需在 `boot.py` 中启用 `usb_cdc.data`。

### 4.4 通信协议
- 单字符 ASCII
- `1` = 亮,`0` = 灭
- 预留 `2`~`9` 给未来的多态 / 颜色扩展
- 老固件遇到不认识的字符即忽略 —— 向前兼容

## 5. 异常处理与边界情况

灯为辅助设备,绝不能因其故障干扰 Claude Code。原则:hook 脚本永远快速、静默、不报错退出。

| 情况 | 处理方式 |
|---|---|
| 灯没插 / 串口找不到 | 脚本静默退出(exit 0) |
| 串口被占用 / 写入失败 | 捕获异常,静默退出 |
| 串口设备名变化 | 按 USB VID `0x2E8A` 自动查找,不硬编码 |
| 脚本卡住 | 串口操作加约 1 秒超时 |
| 板子上电初始状态 | 默认灭 |
| Claude 异常退出未触发 Stop | 固件 10 分钟看门狗超时熄灭 |
| 收到未知字符 | 固件忽略,不崩溃 |

**看门狗取舍**:超时设 10 分钟兜底,不做周期续命(保持简单)。绝大多数 agent 回合几分钟内结束,10 分钟兜底仅在真正异常时生效。若单次任务超过 10 分钟,灯会误灭 —— 属可接受折衷。

## 6. 跨平台兼容(Windows / Ubuntu)

| 方面 | Windows | Ubuntu |
|---|---|---|
| 串口名 | `COM3`、`COM4`… | `/dev/ttyACM0`… |
| 发现方式 | 统一用 `pyserial` 的 `list_ports` 按 USB VID 匹配,同一段代码两边通用 | 同左 |
| Python 命令 | `python` / `py` | `python3` |
| 依赖安装 | `pip install pyserial` | `pip install pyserial` |

- `mc_light.py` 用 `serial.tools.list_ports` 按 VID `0x2E8A` 自动锁定设备,Windows 与 Ubuntu **同一份脚本、零改动**,并顺带解决两系统端口名都会变的问题
- spec 交付时提供两套 hook 配置示例(Windows 用 `python`,Ubuntu 用 `python3`)
- 固件 `code.py` 与操作系统无关,不受影响

## 7. 测试策略

三部分各自可独立验证。

### 7.1 固件层(XIAO `code.py`)
- 板子插电,用串口终端手动发 `1`/`0`,肉眼确认灯亮/灭
- 发未知字符,确认灯不变、不崩
- 发 `1` 后静置,确认约 10 分钟后自动熄灭(测试时可临时把超时改成 10 秒验证)

### 7.2 Hook 脚本层(`mc_light.py`)
- 命令行手动跑 `python mc_light.py on` / `off`,看灯响应
- 拔掉灯再跑,确认静默退出、返回码 0(`echo $?`)
- 串口名故意写错/被占用,确认不报错、不卡住

### 7.3 集成层(Claude Code hooks)
- 配好 hook 后,在 Claude Code 里发一句话,确认灯亮;答完确认灯灭
- 连续几轮对话,确认灯跟着起伏
- 直接关掉终端,确认灯最终(超时后)熄灭

### 验收标准
插上灯用 Claude Code 时,agent 一干活 M 就亮金色,答完就灭;不插灯时 Claude Code 完全正常。
